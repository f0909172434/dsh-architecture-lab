# DSH 架构实验室 (DSH Architecture Lab)

> 一个 DSH 插件与命令行工具，让不同的 DeepSeek 智能体架构在同一批编程任务上接受受控比较。

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [GitHub 源码](https://github.com/Chih-Kai-Wang/dsh-architecture-lab) · MIT License

## 项目简介

**DSH Architecture Lab** 是一套纯后端的 DSH 插件与命令行工具。它让不同的 **AI 智能体（Agent）架构** 处理同一批软件工程任务，再比较它们的解题结果、耗时与 Token 成本。

智能体评测很容易被几件事扭曲：每次运行的提示词不同、不同试验之间共用上下文，或花费没有被计量。本实验室让每个试验在隔离的沙箱中运行，由预算代理计量每一笔请求，再交给独立的裁判用外部测试评分。

目前版本 `0.1.0-dev.9` 是开发预览版。到目前为止，只完成了一组四种配方的真实模型比较。

## 核心特色

- **沙箱隔离**：受试代理在独立的 Lima Linux 虚拟机容器或 macOS Seatbelt 沙箱中运行，每个试验都有自己的内存、文件系统与进程。
- **预算计量**：内置的记账代理以 SQLite 事务锁实时计量每一笔 API 请求，并应用总预算上限，默认为 NT$300。
- **外部裁判**：外部测试在独立的子进程中运行，评分不取决于受试模型对自己工作的说法。
- **四种对照配方**：原生对话、长期记忆、分步规划与两者混合的架构，在相同条件下比较。
- **无头插件与 CLI**：没有网页前端。工具专为命令行运行、批量试验与结构化报告而设计。

## 架构配方

实验室针对 AI 代理架构设计了四种受控配方：

| 配方 | 记忆机制 (Memory) | 规划机制 (Planning) | 架构特点 |
| :---: | :---: | :---: | :--- |
| **A** | 原生 DSH 上下文 | 原生 DSH 直接执行 | **基准对照组**：最精炼的基础推理架构 |
| **B** | **Engram 长期记忆** | 原生 DSH 直接执行 | **记忆增强组**：利用向量嵌入检索历史经验与上下文 |
| **C** | 原生 DSH 上下文 | **Plan-and-Execute** | **规划增强组**：先分解任务为子步骤，依序执行与验证 |
| **D** | **Engram 长期记忆** | **Plan-and-Execute** | **混合完整组**：结合长期经验检索与结构化多步规划 |

## 实测结果 (DeepSeek-V4.1-Flash)

在已冻结的研究协议下，实验室用真实的 **DeepSeek-V4.1-Flash** 模型完成了第一组四重奏，也就是每种配方各跑一次。任务是 `stale-fee`，要修正手续费的业务规则：

| 配方 | 外部测试通过率 | 请求次数 | 实际耗时 | 实际花费 (TWD) | 综合表现 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **配方 A** (原生基准) | **7 / 7 通过** | 6 次 | 16.2 秒 | NT$ 0.1513 | 表现稳定，快速完成修正 |
| **配方 B** (Engram 记忆) | **7 / 7 通过** | 5 次 | **11.0 秒** | **NT$ 0.1441** | 🚀 **速度最快、成本最低**（性价比最高） |
| **配方 C** (分步规划) | **7 / 7 通过** | 12 次 | 44.0 秒 | NT$ 0.3110 | 产出代码完全正确，步骤验证较为严谨 |
| **配方 D** (混合架构) | **7 / 7 通过** | 11 次 | 32.4 秒 | NT$ 0.4201 | 成功整合经验与规划，产出完整说明 |

四种配方都通过了全部 7 项外部测试。使用 Engram 记忆的配方 B 请求次数最少、耗时最短，花费也最低。这只是一个任务上的一次运行，还不足以对这些架构做出一般性的排名。

## 快速上手 (Quick Start)

### 1. 环境需求

- **Node.js**: v24 以上
- **Python**: 3.10 以上
- **虚拟机/容器**：macOS 原生沙箱 或 Lima Linux VM（Docker）

### 2. 本地测试与自检

克隆项目之后，就能在本地直接运行验证，不需要设置 API 密钥：

```bash
# 执行全部 85 项单元与集成测试（平均仅需约 1.7 秒）
npm test

# 检测系统环境、虚拟机、Docker 镜像与定价状态
npm run lab -- doctor
```

### 3. 查看实验室状态

以下命令会显示目前选定的配方、剩余预算与历史试验记录：

```bash
npm run lab -- status
```

## 命令行指令指南 (CLI Guide)

### 研究实验管理 (Research)

```bash
npm run lab -- select B               # 切换当前选定配方 (A/B/C/D)
npm run lab -- check-one              # 执行离线单次合规性验证
npm run lab -- run-one stale-fee 1 B  # 执行指定任务的正式试验
npm run lab -- report                 # 生成并导出研究对比成果报告 (comparison-v2.json)
npm run lab -- stop                   # 安全停止当前正在执行的试验
```

### 日常项目任务 (Daily Mode)

```bash
npm run lab -- daily-import project.json   # 安全导入日常项目快照
npm run lab -- daily-task task.json       # 创建日常任务草稿
npm run lab -- daily-preview <runId>      # 预览任务产生的代码变更
npm run lab -- daily-adopt <runId>        # 采纳变更并写入项目
npm run lab -- daily-export <runId> <dir> # 将成果导出至新文件夹
```

## 项目结构简介

```text
├── src/                # 核心引擎 (Broker 费用代理、Judge 裁判、Manager 协调器)
├── tasks/              # 受控编程任务目录 (涵盖手续费计算、日期边界、金额解析等)
├── test/               # 85 项高覆盖率自动化单元测试
├── state/              # 实验状态持久化目录 (SQLite 注册表、计费账本、研究协议)
├── docs/               # 架构设计文档与实证研究成果
├── containers/         # Linux VM Docker 容器隔离配置与 Supervisor
└── package.json        # 依赖配置与运行脚本
```

## 这些结果还不能说明什么

- 研究计划有六个任务，每种配方在每个任务上各做三次，总共 72 次试验。目前只完成第一组四重奏，其余 17 组已写进冻结的协议，但还没有运行。进度请看[验收状态](docs/acceptance-status.md)。
- 比较报告写在 `state/comparison-v2.json`，这个文件没有提交到仓库，所以上面的数字无法只靠本仓库核对。
- 先前两次小试验已排除在结果之外。[首轮小试验分析](docs/pilot-analysis.md)发现，其中一个试验读到了另一个试验的答案，而当时的外部裁判也可以被绕过。
- 付费的[日常模式](docs/daily-mode.md)任务仍然暂停，要等产品冒烟验收通过。
- v0.1 发布前仍需要独立的最终审查与稳定的产品验收。实验不预设任何架构必须胜出，也不能据此推论 AGI 或持续学习。
