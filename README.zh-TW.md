# DSH 架構實驗室 (DSH Architecture Lab)

> 一個 DSH 外掛與命令列工具，讓不同的 DeepSeek 智能體架構在同一批程式任務上接受受控比較。

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [GitHub 原始碼](https://github.com/f0909172434/dsh-architecture-lab) · MIT License

## 專案簡介

**DSH Architecture Lab** 是一套純後端的 DSH 插件與命令列工具。它讓不同的 **AI 智能體（Agent）架構** 處理同一批軟體工程任務，再比較它們的解題結果、耗時與 Token 成本。

智能體評測很容易被幾件事扭曲：每次執行的提示詞不同、不同試驗之間共用上下文，或花費沒有被計量。本實驗室讓每個試驗在隔離的沙盒中執行，由預算代理計量每一筆請求，再交給獨立的裁判用外部測試評分。

目前版本 `0.1.0-dev.9` 是開發預覽版。到目前為止，只完成了一組四種配方的真實模型比較。

## 核心特色

- **沙盒隔離**：受試代理在獨立的 Lima Linux 虛擬機容器或 macOS Seatbelt 沙盒中執行，每個試驗都有自己的記憶體、檔案系統與程序。
- **預算計量**：內建的記帳代理以 SQLite 交易鎖即時計量每一筆 API 請求，並套用總預算上限，預設為 NT$300。
- **外部裁判**：外部測試在獨立的子程序中執行，評分不取決於受試模型對自己工作的說法。
- **四種對照配方**：原生對話、長期記憶、分步規劃與兩者混合的架構，在相同條件下比較。
- **無頭外掛與 CLI**：沒有網頁前端。工具專為命令列執行、批次試驗與結構化報告而設計。

## 架構配方

實驗室針對 AI 代理架構設計了四種受控配方：

| 配方 | 記憶機制 (Memory) | 規劃機制 (Planning) | 架構特點 |
| :---: | :---: | :---: | :--- |
| **A** | 原生 DSH 上下文 | 原生 DSH 直接執行 | **基準對照組**：最精簡的基礎推理架構 |
| **B** | **Engram 長期記憶** | 原生 DSH 直接執行 | **記憶增強組**：利用向量嵌入檢索歷史經驗與上下文 |
| **C** | 原生 DSH 上下文 | **Plan-and-Execute** | **規劃增強組**：先分解任務為子步驟，依序執行與驗證 |
| **D** | **Engram 長期記憶** | **Plan-and-Execute** | **混合完整組**：結合長期經驗檢索與結構化多步規劃 |

## 實測結果 (DeepSeek-V4.1-Flash)

在已凍結的研究協定下，實驗室用真實的 **DeepSeek-V4.1-Flash** 模型完成了第一組四重奏，也就是每種配方各跑一次。任務是 `stale-fee`，要修正手續費的業務規則：

| 配方 | 外部測試通過率 | 請求次數 | 實際耗時 | 實際花費 (TWD) | 綜合表現 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **配方 A** (原生基準) | **7 / 7 通過** | 6 次 | 16.2 秒 | NT$ 0.1513 | 表現穩定，快速完成修正 |
| **配方 B** (Engram 記憶) | **7 / 7 通過** | 5 次 | **11.0 秒** | **NT$ 0.1441** | 🚀 **速度最快、成本最低**（性價比最高） |
| **配方 C** (分步規劃) | **7 / 7 通過** | 12 次 | 44.0 秒 | NT$ 0.3110 | 產出代碼完全正確，步驟驗證較為嚴謹 |
| **配方 D** (混合架構) | **7 / 7 通過** | 11 次 | 32.4 秒 | NT$ 0.4201 | 成功整合經驗與規劃，產出完整說明 |

四種配方都通過了全部 7 項外部測試。使用 Engram 記憶的配方 B 請求次數最少、耗時最短，花費也最低。這只是一個任務上的一次執行，還不足以對這些架構做出一般性的排名。

## 快速上手 (Quick Start)

### 1. 環境需求

- **Node.js**: v24 以上
- **Python**: 3.10 以上
- **虛擬機/容器**：macOS 原生沙盒 或 Lima Linux VM（Docker）

### 2. 本地測試與自檢

複製專案之後，就能在本機直接執行驗證，不需要設定 API 金鑰：

```bash
# 執行全部 85 項單元與整合測試（平均僅需約 1.7 秒）
npm test

# 檢測系統環境、虛擬機、Docker 鏡像與定價狀態
npm run lab -- doctor
```

### 3. 查看實驗室狀態

以下命令會顯示目前選定的配方、剩餘預算與歷史試驗紀錄：

```bash
npm run lab -- status
```

## 命令列指令指南 (CLI Guide)

### 研究實驗管理 (Research)

```bash
npm run lab -- select B               # 切換當前選定配方 (A/B/C/D)
npm run lab -- check-one              # 執行離線單次合規性驗證
npm run lab -- run-one stale-fee 1 B  # 執行指定任務的正式試驗
npm run lab -- report                 # 產生並匯出研究對比成果報告 (comparison-v2.json)
npm run lab -- stop                   # 安全停止當前正在執行的試驗
```

### 日常專案任務 (Daily Mode)

```bash
npm run lab -- daily-import project.json   # 安全匯入日常專案快照
npm run lab -- daily-task task.json       # 建立日常任務草稿
npm run lab -- daily-preview <runId>      # 預覽任務產生的代碼變更
npm run lab -- daily-adopt <runId>        # 採納變更並寫入專案
npm run lab -- daily-export <runId> <dir> # 將成果匯出至新資料夾
```

## 專案結構簡介

```text
├── src/                # 核心引擎 (Broker 費用代理、Judge 裁判、Manager 協調器)
├── tasks/              # 受控程式任務目錄 (涵蓋手續費計算、日期邊界、金額解析等)
├── test/               # 85 項高覆蓋率自動化單元測試
├── state/              # 實驗狀態持久化目錄 (SQLite 註冊表、計費帳本、研究協定)
├── docs/               # 架構設計文檔與實證研究成果
├── containers/         # Linux VM Docker 容器隔離設定與 Supervisor
└── package.json        # 依賴配置與執行腳本
```

## 這些結果還不能說明什麼

- 研究計畫有六個任務，每種配方在每個任務上各做三次，總共 72 次試驗。目前只完成第一組四重奏，其餘 17 組已寫進凍結的協定，但還沒有執行。進度請看[驗收狀態](docs/acceptance-status.md)。
- 比較報告寫在 `state/comparison-v2.json`，這個檔案沒有提交到 repo，所以上面的數字無法只靠本 repo 核對。
- 先前兩次小試驗已排除在結果之外。[首輪小試驗分析](docs/pilot-analysis.md)發現，其中一個試驗讀到了另一個試驗的答案，而當時的外部裁判也可以被繞過。
- 付費的[日常模式](docs/daily-mode.md)任務仍然暫停，要等產品冒煙驗收通過。
- v0.1 發布前仍需要獨立的最終審查與穩定的產品驗收。實驗不預設任何架構必須勝出，也不能據此推論 AGI 或持續學習。
